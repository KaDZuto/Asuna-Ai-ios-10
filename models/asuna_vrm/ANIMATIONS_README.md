# Анимации Asuna VRM — источник и лицензия

## Что это

27 файлов `.vrma` (VRMC_vrm_animation) — настоящие motion-capture анимации,
ретаргетнутые с Mixamo на нормализованный VRM-скелет. В отличие от
процедурного покостного твининга (`vrm-gestures.js`), это записанное движение
реального человека — руки, корпус, ноги двигаются связно, без «робота».

## Источник

Файлы взяты из открытого репозитория
[Dongping-Chen/Clawatar](https://github.com/Dongping-Chen/Clawatar) (лицензия
MIT), у которого в `public/animations/` лежит набор из 162 таких клипов.
Сами анимации происходят из **Mixamo (Adobe)** — Clawatar их уже
сконвертировал в `.vrma` и распространяет вместе с MIT-лицензированным кодом.

Mixamo даёt право свободно использовать их анимации как часть готового
продукта/персонажа (именно наш случай — они запечены в десктоп-компаньона).
Официальные условия: https://helpx.adobe.com/creative-cloud/faq/mixamo-faq.html.
Мы не юристы — если планируете коммерческое распространение приложения
в широком масштабе, стоит перечитать актуальные условия Adobe самостоятельно.
Для личного/некоммерческого использования это стандартный и повсеместно
принятый паттерн (тем же путём идут VSeeFace, VRM-плагины для Unity и т.п.).

## Файлы и manifest

`animations_manifest.json` в этой же папке — единственное место, которое
знает про реальные имена файлов. `vrm-clip-engine.js` и `vrm-engine.js`
работают только с "дружественными" ключами (`wave`, `dance`, `jump`,
`turn_left`, …), поэтому переименовать/добавить файл — значит просто
поправить/дописать запись в manifest, код трогать не нужно.

## Как добавить остальные анимации из Clawatar (132 штуки всего)

Из 132 файлов пакета сюда отобраны вручную только 27 самых полезных
(waves/nod/shrug/bow/jump/несколько танцев). Чтобы забрать оставшиеся —
запустите из корня репозитория:

```bash
node scripts/fetch-more-animations.js
```

Скрипт сам:
1. клонирует Clawatar во временную папку,
2. копирует все `.vrma`, которых ещё нет в `animations/`,
3. дописывает (не перезаписывая существующие ключи) `animations_manifest.json`.

Примечание: скрипт сравнивает по автосгенерированному имени файла, а не по
содержимому — часть уже отобранных вручную 27 клипов (например `wave.vrma`)
попадёт в новый набор ещё раз под своим "сырым" именем (`waving.vrma`). Это
не ломает ничего (просто два ключа с одинаковой анимацией) — при желании
удалите дубль из manifest вручную.

После этого — `npm run build:vrm`, чтобы пересобрать `renderer/vrm-bundle.js`
(нужно один раз после `git pull`/после изменения `vrm-bundle.entry.mjs`, для
самих `.vrma` пересборка бандла не требуется — они грузятся `fetch()` в рантайме).

## Если хотите анимации получше/побольше — Mixamo напрямую

Скрипт выше берёт готовый пакет, но у Mixamo (mixamo.com) конвертированных
под VRM анимаций в десятки раз больше, включая то, чего нет в Clawatar.
Это требует ручного шага (бесплатный Adobe-аккаунт + браузер, автоматизировать
скачивание без логина нельзя):

1. mixamo.com → выбрать анимацию → скачать FBX **"Without Skin"**.
2. Blender + аддон [VRM Add-on for Blender](https://vrm-addon-for-blender.info/en/)
   → импортировать FBX, ретаргетнуть `mixamorig:*` → VRM humanoid bones
   (в самом аддоне есть готовый пресет ретаргета под Mixamo).
3. Экспортировать как `.vrma` в `resources/models/asuna_vrm/animations/`.
4. Добавить строку в `animations_manifest.json`.

Дальше всё работает само — `vrm-clip-engine.js` не знает и не должен знать,
откуда взялся файл.
